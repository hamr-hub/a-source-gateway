加源指南

这是本项目最主要的日常任务。把一个官方公开的数据源接进来,只需要改数据文件: 九步流程,每一步都有明确的命令、产出和判据,最后交出可复制的调用示例 + 真实返回的数据。 这一页既写给人看,也写给 AI 智能体照着做。

加源是什么:只改数据文件,不改代码

网关只存源元数据索引,数据按需实时取。所以"加一个源"本质上是 往几张表里写几行 —— Go 网关与 Python 解析面在启动时从同一份 data/ 构建注册表, 不需要改任何一行 Python 或 Go 代码。

要加什么改哪个文件
源基本信息(海外 / 全球 / 多国)data/source_inventory.csv 加一行(17 列)
源基本信息(中国国内)data/source_inventory_cn.csv 加一行(18 列)
端点定义data/endpoints.json 的 sources 下加键
常用简称 / 别名data/aliases.json 的 aliases 对象里加键
!三条不可违反的硬规则
  1. 合法性优先于功能 —— 只接入官方公开、允许程序化访问的数据源。不绕限速、不加代理池、不接入需要登录/付费才能读的数据。
  2. 不许编造 —— 每个字段都要能追溯到上游文档、真实请求,或维护者的明确说明。拿不准就留空或写"未实测"。
  3. 加源不改代码 —— 不要为了加源去改 python/src/ 下的任何文件,也不要往 Go 代码里硬编码源、端点或别名。

步骤 0 —— 合规前置检查(30 秒)

在动手之前先回答这三个问题,任何一个答不上来就先问用户:

  1. 这个数据是不是法规强制公开,或官方免费开放的?

    答不上来 → 先问用户。不要靠"看起来像公开数据"下判断。

  2. 官方条款 / robots 是否允许程序化访问?

    答不上来 → 先问用户。不允许程序化访问的站点,再开放也不接。

  3. 它是否公布了限速口径?

    没有公布也行,但要写清"未公布"或"实测观察到" —— 不能空着,也不能编一个数字。 限速是授权条件,不是技术障碍。

九步流程

每一步都给了「做什么 / 命令 / 产出 / 判据」。步骤 6 是证据关卡,不能跳过。

  1. 步骤 1 · 侦察目标站点

    做什么:探测可达性、状态码、内容类型、延迟、认证要求(401/403/WWW-Authenticate)、限速响应头(X-RateLimit-*/Retry-After)、常见 API 文档端点(/openapi.json、/swagger.json、/api-docs 等,最多约 20 次探测),以及 JSON 响应里列表所在路径和总数所在路径的启发式推断。

    bash
    python3 scripts/recon.py https://api.example.org/works -o /tmp/recon.json

    常用参数:--contact you@example.org(很多官方 API 要求 UA 带邮箱)、--timeout 8、--no-probe(跳过路径发现)。

    产出:/tmp/recon.json。每个推断字段都带 inference(推断依据);无法确定的字段是 null 并且有 warnings。

    判据:状态码正常、没有解释不了的 warnings。若报 403 而站点文档要求 UA 带邮箱,设 A_GATEWAY_CONTACT=you@example.com 后重试。

  2. 步骤 2 · 补齐语义(这一步需要判断,不能自动化)

    做什么:侦察能测出"接口长什么样",测不出"这数据干什么、更新多快、限速怎么算"。 靠读上游文档 + 领域判断补齐下面这些字段。

    字段从哪来典型写法
    分类你的判断,取自现有十族七、学术与文献
    机构 / 国别上游官方站点美国SEC / 美国
    数据内容上游文档申报文件全文/XBRL财报/Form4内部人
    认证方式必须用分类器认识的写法(见下方取值表)无key
    官方限速口径上游文档原文官方约10次/秒
    实测规模真实请求拿到的数字 + 计数口径实测 1234567 条(接口 total 字段)
    实测增量真实观测约 3300 份/日(按 daily-index 增量)
    代理需求 / 合规风险你的判断不走代理 / 低
    建议采集方式你的判断按 published_date 增量

    产出:一张填满的字段表,每个值都有出处。

    判据:实测增量 不能等于 实测规模(make validate 会拦);实测规模 要写清计数口径,不能只写一个孤零零的数字。

  3. 步骤 3 · 生成草稿

    做什么:用侦察报告 + 你补的语义生成一行 CSV、一个端点定义和一份待办清单。默认写到草稿目录,不动真实数据文件。

    bash
    python3 scripts/scaffold_source.py \
  --recon /tmp/recon.json \
  --name "Example Journal API" \
  --family "七、学术与文献" \
  --org "Example Journal" \
  --country "全球" \
  --summary "期刊论文元数据与引用" \
  --out-dir /tmp/draft

    产出(都在 /tmp/draft/):

    • source_inventory.row.csv —— 可直接粘进对应清单的一行
    • endpoints.entry.json —— 可直接粘进 data/endpoints.json 的端点定义
    • REPORT.md —— 每个字段的来源,以及仍需人补的 TODO 项(限速口径、规模口径、增量策略)

    落哪份清单由 --country 决定:--country '中国' → data/source_inventory_cn.csv (国内行多一列 优先级,用 --priority P0|P1|P2 指定);其余 → data/source_inventory.csv。

    看完 REPORT.md 的 TODO 补齐后再落盘:

    bash
    python3 scripts/scaffold_source.py --recon /tmp/recon.json --name "..." --apply

    判据:REPORT.md 里的 TODO 全部补齐才能 --apply。--apply 是幂等保护式的:源名已存在就拒绝执行。

  4. 步骤 4 · 加别名

    做什么:编辑 data/aliases.json,在 aliases 对象里加一项(让 LLM、简称也能找到它)。

    json
    {
  "version": "1.0",
  "aliases": {
    "My Journal API": ["mja", "myjournal"]
  }
}

    产出:data/aliases.json 多一项。

    判据:键必须精确等于 CSV 里 数据源 那一列的值; 必须嵌在 aliases 对象里(见下方「常见坑」)。 已接入的国内源必须有 ASCII 别名。

  5. 步骤 5 · 校验

    做什么:

    bash
    make validate          # 等价于 python3 -m a_source_gateway.cli validate

    它检查两份清单(source_inventory.csv + source_inventory_cn.csv): 列齐全、源名不重复、官方入口是 URL、实测增量 非空且不等于 实测规模、 认证方式取值能被分类器识别、没有残留的 TODO(…) 占位符、 endpoints.json 的每个键在两份清单合计里能找到对应行、每个端点有 url_template 与 response、 必填参数都有 example 或 default、URL 里用了 {size} 就必须声明 size 参数; 另外还查国别归属、跨文件重名、优先级取值(P0/P1/P2)与已接入国内源的 ASCII 别名。

    判据:make validate 退出码 0。

  6. 步骤 6 · 用真实数据验证(证据关卡,不能跳过)

    做什么:真的去请求上游,然后断言你声明的元数据。

    bash
    python3 scripts/verify_source.py "My Journal API" --direct-only

    断言这四件事:

    • 声明的 response.item_path 在真实响应里确实指向一个列表;
    • 声明的 response.total_field 确实是一个数字;
    • response.fields 里声明的字段名在返回条目里确实出现;
    • 本次调用没有降级(降级的调用不算"验证通过")。

    退出码:0 已用真实数据验证通过 / 1 断言失败或调用降级 / 2 根本连不上上游(环境问题,不是源的问题 —— 如实报告,不要伪造)。另外 2 也用于参数非法、注册表载入失败这类用法错误。

    !为什么建议加 --direct-only,以及两条都要跑

    走网关时上游预算只有 400ms,而从中国到欧美上游的实测往返常常是 0.4–7.5s —— 于是调用会正常地降级,not_degraded 断言随之失败、退出码变成 1。 那不是元数据写错了,是网络慢。 --direct-only 让验证脚本直连上游(带自己的超时),不受网关 400ms 预算影响,才能真正回答"我声明的字段对不对"。

    代价:直连验证不覆盖网关这一段。所以两条都要跑:

    bash
    python3 scripts/verify_source.py "My Journal API" --direct-only   # 元数据对不对
python3 scripts/verify_source.py "My Journal API"                  # 网关在预算内能不能通

    第二条在网络慢时返回 DEGRADED + 退出码 1,这是预期行为,不是源有问题; 它证明的是"网关在预算内优雅降级并给出直连兜底"。关键是它必须给出 fallback.upstream_url。

    退出码是 1 时先看断言名:

    • not_degraded 失败 → 网络/预算问题,元数据可能完全正确,别去改元数据;
    • item_path_resolves_to_list / total_field_resolves_to_number 失败 → 元数据写错了,去改。

    判据:--direct-only 退出码 0,且输出里有真实响应样本。

  7. 步骤 7 · 更新部署

    做什么:让网关重新加载注册表。

    bash
    make up                 # docker compose up -d --build
make gateway-run        # 或本地直接跑 Go 网关

    产出:跑起来的网关加载了新注册表。

    判据:GET /v1/sources 里能看到新源。只改数据文件时,重启即可生效(注册表在进程启动时从 data/ 构建);改了代码才需要重新 build。

  8. 步骤 8 · 给出调用示例和真实数据(交付物)

    做什么:产出三样东西,原样贴给你的用户:

    1. 端点说明(干什么的、必填参数、限速口径);
    2. 一条可复制粘贴的 curl 命令;
    3. 真实的响应信封(data 截断到前 1–2 条)。
    bash
    python3 scripts/demo.py "My Journal API" --limit 2

    判据:输出里有真实数据,不是占位符。demo.py 遇到降级会非零退出 —— 它不拿降级数据当"跑通了"给人看。

  9. 步骤 9 · 收尾

    bash
    make check              # ruff + mypy + pytest + 数据校验 + Go 构建/测试 + 注册表 parity + 文档站自检

    然后提 PR。PR 描述必须包含:官方入口、限速口径、规模与增量的取法、合规风险判断依据,以及步骤 6/8 的真实输出片段。

    判据:make check 全绿,PR 里带着真实请求输出。

认证方式取值表

分类器是规则表匹配(见 python/src/a_source_gateway/registry.py 的 AUTH_RULES),写了它不认识的值会被 make validate 拦下。 推荐用下表左边这一列的写法:

推荐写法含义规则表里也认的等价写法
无key完全不需要任何凭据无 key、无需
需邮箱只要 UA 里带联系邮箱(最常见)邮箱
免费key免费注册拿 keyapi key
可注册key可以注册,可能免费也可能收费—
可选key有 key 更好,没 key 也能用—
需token要 bearer tokentoken、oauth
部分付费一部分接口要钱需付费
账号+付费必须账号并且付费—
免费/付费分档:免费版和付费版—
部分免费部分付费按数据分档—
多数免费大部分免费,少部分收费—
部分注册只有部分接口要注册—
!不要写"无key"以外的任意含 key 的词

历史 bug:用 "key" in text 判定,会把 65 个"无key"的源误判成需要 key。 现在是规则表匹配,并且 可选 + key 必须优先于 无key 判定。 自造写法(如 需要APIKey)会被 validate 拦下。

两份清单怎么选:只看「国别」列

本仓库有两份源清单,按 国别 列分工,一行只属于一份清单。 判定用的是 a_source_gateway.registry.CN_COUNTRIES / is_cn_country(), 脚本与校验器都从这一处取。

清单文件装什么列网关运行时是否加载
data/source_inventory.csv 海外源(国别 = 美国 / 欧盟 / 英国 / 全球 / 多国 / …) 17 列 ✅ 全量加载
data/source_inventory_cn.csv 国内源(国别 ∈ {中国, 中国大陆, 中华人民共和国}) 18 列(= 17 列契约 + 优先级) ⚠️ 只加载"已接入"的行
  • 国别 ∈ {中国, 中国大陆, 中华人民共和国} → 落 data/source_inventory_cn.csv
  • 其余一律(全球 / 多国 / 欧盟 / 美国 / 中国香港…) → 落 data/source_inventory.csv

中国香港是单独法域,留在海外清单 —— 所以这里是白名单而不是前缀匹配。 不要靠源名、域名或"这是个新源"来猜归属。

「已接入」与「候选」是机器可判定的

  • 一个国内源在 data/endpoints.json 里有端点定义 → 已接入 → 运行时加载它;
  • 只在 CSV 里、没有端点定义 → 候选 → 运行时不加载(候选源不会污染网关的源列表)。

所以国内清单里可以放很多"还没接入"的高优先级候选,不用急着给它们编端点定义 —— 没跑通 verify_source.py 的源不许进 endpoints.json。

常见坑

别名写在了顶层
两个加载器(Go 与 Python)只读 aliases 这个键。写成顶层键会被静默忽略 —— validate 照样通过,但别名永远不生效。
国内源 id 会漂移
源名是中文时 id 会退化成 src_<行号>,清单一增删就整体平移。所以已接入的国内源必须有 ASCII 别名,make validate 会检查这条。
国内源被抄进海外清单
两份都有,改字段时必然漂移(哪份是真的说不清)。国内行原地保留在 source_inventory_cn.csv,海外清单不动。
残留 TODO(…) 占位符
make validate 会直接拦下。骨架里的 TODO(…) 必须换成真实值或明确的"未实测"。
国内源的 --apply 只写清单
国内源的 --apply 只写国内清单(候选池),不写 endpoints.json。还要单独补端点定义与别名才算接入网关。
候选源污染源列表
只在 CSV 里、没有端点定义的国内源是候选,运行时不加载。别急着给候选编端点定义。

另外几条容易踩的:

  • 必填参数缺 example —— make validate 会拦;端点声明的 url_template 用了 {size} 就必须声明 size 参数。
  • 认证方式自造写法 —— 见上面的取值表,规则表不认就会被 validate 拦下。
  • 把降级当成"源写错了" —— 跨境源首次调用降级是预期行为。先看断言名:not_degraded 失败是网络问题,item_path_resolves_to_list 失败才是元数据问题。
  • 把凭据写进仓库 —— A_GATEWAY_CONTACT 是联系邮箱不是密钥;它写进 User-Agent,不带邮箱 SEC 直接 403。所有凭据只走环境变量。
  • data/ 下的新文件没进分发路径 —— 四处都要加:pyproject.toml 的 force-include、.github/workflows/release.yml 的 tarball 拷贝、deploy/README.md 的 systemd 安装命令、python/Makefile 的 sync-data。漏装的症状:线上注册表比仓库少源。

Definition of Done

一个"新增数据源"的改动,只有同时满足下面全部条件才算完成:

  1. make validate 通过。
  2. make check 通过(ruff / mypy / pytest / Go 构建与测试 / parity / 文档站自检)。
  3. python3 scripts/verify_source.py <源名> --direct-only 退出码为 0,且输出里有真实响应样本。
  4. python3 scripts/verify_source.py <源名>(走网关)要么退出码 0,要么是 DEGRADED(网络慢时的预期结果 —— 关键是它必须给出 fallback.upstream_url)。
  5. data/aliases.json 已加别名(除非该源名称本身就是唯一标识)。
  6. python3 scripts/demo.py <源名> 的输出已附在 PR 描述里(调用示例 + 真实数据)。
  7. PR 描述写清了:官方入口、限速口径、规模与增量的取法、合规风险判断依据。
  8. 没有改动 python/src/ 下的 Python 业务逻辑(加源只改数据文件)。

PR 描述要写什么

一份合格的加源 PR 描述,让没参与开发的人也能复核:

  1. 官方入口

    完整 URL + 最近一次链接校验的状态码。

  2. 限速口径

    官方公布的原文;没公布就写"未公布"或"实测观察到 …",并说明依据。

  3. 规模与增量的取法

    不只是数字,还要说清怎么数出来的(哪个接口的哪个字段、什么时间窗口)。

  4. 合规风险判断依据

    依据哪份官方条款 / robots / 政策页,得出"低/中/高"哪一档。

  5. 步骤 6 / 8 的真实输出片段

    贴 verify_source.py 与 demo.py 的真实终端输出,不能只写"应该可用"。

✓人保留判断,AI 干重复劳动

智能体做重复劳动:侦察、生成草稿、跑验证、产出调用示例。 人类维护者保留判断:合规判定、限速口径确认、代码评审、合并。 涉及新增源类型的 PR 需要一位维护者评审数据字段的真实性。
