A 类数据源的通用网关

SEC EDGAR、Companies House、GLEIF、OFAC、ClinicalTrials.gov、OpenAlex、Crossref…… 这些源的数据都免费公开，但接口形态、限速口径、增量策略、返回结构各不相同。 a-source-gateway 把这些差异收敛成一层统一信封： 不存业务数据，只保留源元数据索引；数据按需实时取；单次调用硬预算 ≤500ms。

三分钟跑通第一个查询

本机需要 Docker；没有的话见快速部署里的本地二进制方式。

  1. 起服务

    bash
    git clone https://github.com/hamr-hub/a-source-gateway.git
cd a-source-gateway
cp .env.example .env
$EDITOR .env          # 把 A_GATEWAY_CONTACT 改成你的真实邮箱

make up                # docker compose up -d --build

    A_GATEWAY_CONTACT 是联系邮箱、不是密钥，但它会写进 User-Agent——SEC、OpenAlex 等上游据此识别调用方，不带邮箱 SEC 直接 403。

  2. 确认它活着

    console
    $ curl -s http://127.0.0.1:8848/readyz | python3 -m json.tool
{
    "ok": true,
    "sources": 116,
    "offline": false
}

    /livez = 进程活着；/readyz = 注册表已加载、能接流量。

  3. 查一次

    bash
    curl -s -X POST http://127.0.0.1:8848/v1/query \
  -H 'Content-Type: application/json' \
  -d '{"source":"gleif_lei","endpoint":"lei_records","params":{"size":2},"limit":2}'

第一次调用大概率会"降级"——这是设计,不是故障

网关给上游取数留的墙钟预算是 400ms，留 100ms 给解析与序列化。 从中国直连欧美上游，实测往返常常是 0.4–7.5s——于是第一次调用通常会超时。 这时网关不会挂死，而是返回一个带 degraded=true 与 fallback.upstream_url 的信封，让你可以立刻直连上游。

降级的同时网关会在后台补数。再调一次同一个查询，就直接命中缓存：

"latency_ms": 1,

完整的信封字段、缓存语义、错误类型和降级兜底策略，见 信封与降级。

接口一览

网关一共 14 条路由，其中取数据与列源这几条返回统一信封，其余是元数据与运维接口。完整参数与错误码见 API 参考。

方法路径用途
GET/v1/sources?family=&q=列源（可按分类/关键词过滤）
GET/v1/sources/{source_id}单个源的完整元数据
GET/v1/sources/{id}/endpoints/{eid}端点的请求参数与响应结构
POST/v1/query查数据，返回统一信封
GET/v1/query?source=&endpoint=&params=<json>同 POST，便于浏览器直接打开
POST/v1/search一次请求扇出多个源，返回信封数组 + 汇总 meta
GET/v1/schema网关自身的 meta 规范
GET/v1/stats缓存命中率、预热状态、解析引擎
GET/openapi.jsonOpenAPI 3.1 描述（代码生成器可直接吃）
GET/metricsPrometheus 指标
GET/livez /readyz /healthz存活 / 就绪 / 健康探针

这个网关替你做了什么

统一接口形态
所有已接入的源与端点，参数、响应结构、错误语义全部收敛成同一套信封。
时间预算兜底
500ms 硬上限。做不到时优雅降级并给出直连兜底，绝不挂死调用方。
元数据先行
先读元数据再决定怎么查——限速口径、规模、增量、合规风险都在里面。
加源不改代码
新源只改 data/ 下的数据文件，Go 与 Python 两平面自动同步。

一句提醒

!网关只接入官方公开、允许程序化访问的数据源

限速是授权条件，不是技术障碍。本项目不接受需要登录/付费才能读的数据， 不接受明确禁止自动化抓取的站点，也不提供代理池或 IP 轮换来绕过官方限速。 每个源的限速口径、合规风险都记录在源元数据里，可随时核对。
