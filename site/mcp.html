MCP 集成

MCP server 把网关的 5 个核心能力暴露成工具,让 AI 智能体用"先读元数据、再取数"的方式查 A 类数据源。 工具调用默认转发给 Go 网关,网关不可达时才回落进程内 Python resolver —— 回落是可观测的,结果里的 meta.gateway 会写明走的是哪条平面。

5
MCP 工具
2
工作平面(Go / Python)
≤500ms
单次调用硬预算

日志通道

两平面架构

网关本身是Go 做传输与调度、Python 做解析的双平面。网关不可达时,MCP server 会在自己的进程里建一个 Python resolver, 让 MCP 端单独也能用 —— 但这条路径只用于兜底,正常情况下所有查询都走 Go 网关,保证"查询"只有一份实现。

先有网关
MCP server 只是网关的客户端。先按快速部署把 Go 网关跑起来,工具调用才有完整的元数据与缓存。
返回的是信封
所有工具都返回 {meta, data, fields},与 HTTP API 一致。降级语义见「信封与降级」。
一一对应 HTTP 路由
每个工具都映射到一个网关路由,想看完整参数与错误码,直接查 API 参考。
两处要配
网关侧配 A_GATEWAY_CONTACT;MCP 侧配 A_GATEWAY_CONTACT 与 A_GATEWAY_URL。

五个工具

工具作用必填入参对应 HTTP 路由
list_sources列源(可按分类/关键词过滤)无GET /v1/sources
get_source_meta取单个源的完整 metasourceGET /v1/sources/{source_id}
describe_endpoint取端点的请求/响应结构source、endpointGET /v1/sources/{id}/endpoints/{eid}
query_source执行查询,返回信封source、endpointPOST /v1/query
get_meta_schema取网关自身的 meta 规范无GET /v1/schema

推荐用法是 list_sources 定位源 → get_source_meta 看限速与合规 → describe_endpoint 看参数 → query_source 取数。服务给客户端的 instructions 里也是这么写的。

list_sources —— 列出 A 类数据源

按分类或关键词列出可用数据源(轻量投影,不含端点详情)。

入参类型默认说明
familystring空分类关键词,如 制裁
qstring空关键词,搜名称/描述/机构/国别
limitinteger501–500

get_source_meta —— 取数据源元数据

返回单个源的完整 meta:认证方式、官方限速、规模、增量、抓取方式、代理策略、合规风险与端点列表。

入参类型必填说明
sourcestring必填源 id,如 ofac_sdn

返回的 meta 里包含 auth(认证方式)、limits(官方限速)、scale(规模)、increment(增量策略)、 crawl(抓取方式)、proxy_policy(代理策略)、risk(合规风险)与 endpoints(端点列表)。

describe_endpoint —— 描述端点请求与响应

返回端点的请求参数(名称/位置/类型/必填/正则/示例)与响应结构(字段/列表路径/总数字段)。

入参类型必填说明
sourcestring必填源 id
endpointstring必填端点 id
json
{
  "meta": {
    "source": "gleif_lei",
    "endpoint": "lei_records",
    "schema_version": "1.2"
  },
  "data": {
    "source": { "id": "gleif_lei", "name": "GLEIF LEI", "...": "源元数据" },
    "endpoint": {
      "id": "lei_records",
      "name": "LEI 记录检索",
      "method": "GET",
      "params": [
        {
          "name": "size",
          "type": "int",
          "required": false,
          "desc": "每页条数(最大 200)",
          "default": 10,
          "in": "query"
        },
        {
          "name": "page",
          "type": "int",
          "required": false,
          "default": 1,
          "in": "query"
        }
      ],
      "page_size": null,
      "budget_ms": 400,
      "response": {
        "media_type": "application/json",
        "shape": "object",
        "fields": [
          { "name": "data", "type": "array" },
          { "name": "meta.pagination.total", "type": "int" }

}

上面是 gleif_lei 的 lei_records 端点的真实结构(源元数据部分已省略):参数带 in(位置)、required(必填)、pattern(正则)、example(示例),响应带 item_path(列表路径)与 total_field(总数字段)。

query_source —— 查询数据源

按端点定义发起查询,返回信封 {meta, data, fields}。硬预算 ≤500ms,超时自动降级并标注 degraded=true。

入参类型默认说明
sourcestring必填源 id
endpointstring必填端点 id
paramsobject{}端点参数,键为参数名
fieldsarray<string>空只返回这些字段
limitinteger201–500
sincestring无增量窗口起点,如 2026-10-01
timeout_msinteger50050–500

get_meta_schema —— 取 meta 规范

返回网关自身的 meta 规范(源/端点/请求/响应信封的字段定义)。无入参。

接入客户端

安装

bash
pip3 install .              # 从仓库根装

装完得到两个入口:a-source-gateway-mcp(MCP server,stdio)和 a-source-gateway mcp(同一个服务的 CLI 写法)。 不想装包也可以直接跑模块:python3 -m a_source_gateway.mcp_server。

客户端配置

仓库里的样例在 examples/mcp_client.json:

json
{
  "mcpServers": {
    "a-source-gateway": {
      "command": "a-source-gateway-mcp",
      "args": [],
      "env": {
        "A_GATEWAY_CONTACT": "you@example.com"
      }
    }
  }
}

不用装包就换成模块调用,并把网关地址显式写上:

json
{
  "mcpServers": {
    "a-source-gateway": {
      "command": "python3",
      "args": ["-m", "a_source_gateway.mcp_server"],
      "env": {
        "A_GATEWAY_CONTACT": "you@example.com",
        "A_GATEWAY_URL": "http://127.0.0.1:8848"
      }
    }
  }
}
✓A_GATEWAY_CONTACT 填真实邮箱

它是联系邮箱、不是密钥,但会写进 User-Agent:SEC、OpenAlex 等上游据此识别调用方,不带邮箱 SEC 直接 403。

UA 是哪个进程发的,取决于走哪条平面:走 Go 平面时是网关进程的 A_GATEWAY_CONTACT; 走回落平面时是 MCP server 进程的 A_GATEWAY_CONTACT。两边都配上最稳妥。

回落语义

MCP server 默认把工具调用转发给 Go 网关的 HTTP API,地址取自 A_GATEWAY_URL(默认 http://127.0.0.1:8848)。

情况行为meta.gateway
网关可达转发给 Go 网关"go"
网关连不上(连接被拒 / 超时 / 域名解析失败)回落进程内 Python resolver"python-fallback"
网关活着但返回 4xx / 5xx不回落,按业务错误返回"go"

回落是可观测的:结果信封里的 meta.gateway 标明走的是哪条平面,而且每次回落都会写一行 stderr 日志 —— 不静默降级。

console
[mcp-server] Go 网关不可达(http://127.0.0.1:59999): URLError: <urlopen error [Errno 61] Connection refused>; 回落到本地 Python resolver
[mcp-server] tool=list_sources gateway=python-fallback
!stdout 是协议通道,日志一律走 stderr

MCP 的 stdout 传的是协议帧,任何往 stdout 打的日志都会破坏会话。所以回落日志、工具调用日志都写 stderr。 调试时把 stderr 重定向出来看,别去翻 stdout。

排障

症状先查
客户端报找不到命令which a-source-gateway-mcp;或改用 python3 -m a_source_gateway.mcp_server
meta.gateway 是 python-fallbackGo 网关没起或地址不对:curl -s http://127.0.0.1:8848/livez;地址用 A_GATEWAY_URL 覆盖
meta.gateway 是 go 但报 4xx / 5xx网关活着,这是业务错误,不会回落;按 信封与降级处理
回落时列不出源回落路径靠本机的 data/ 建注册表;用 A_GATEWAY_DATA_DIR 指向事实源目录
上游 403A_GATEWAY_CONTACT 没设成真实邮箱
meta.errors 里是 contact_required该源要求 UA 带联系邮箱,但当前平面没配 A_GATEWAY_CONTACT —— 按信封里的 hint 设好再试
查询超时但没报错信封里 degraded=true + meta.fallback.upstream_url,见 信封与降级
日志里什么都没有日志全在 stderr,不是 stdout

工具的完整 HTTP 等价物在 API 参考;降级信封怎么读在 信封与降级; 网关没起来就先看 快速部署。
