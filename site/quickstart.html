快速部署

a-source-gateway 是单容器双进程形态:Go 网关负责 HTTP 服务与调度,Python 解析 worker 负责内容与结构。 下面四种方式都给出可复制的命令、验证和回滚路径 —— 按场景挑一种,别混着来。

8848
默认监听端口
500ms
单次调用硬预算
2
k8s 默认副本数
10001
容器运行 uid/gid

选哪种部署方式

方式场景依据文件
Docker Compose本机 / 单机 / 开发验证docker-compose.yml
systemd单台长期运行的服务器deploy/systemd/a-source-gateway.service
Kubernetes集群、多副本deploy/k8s/
本地二进制开发调试 / 没有 Docker 的环境Makefile 的 gateway-run

先记住三件事

!改 data/ 要重启;缓存不落盘;邮箱不是密钥
  1. 改了 data/ 下的数据文件必须重启。注册表在进程启动时从 data/ 构建。 Compose 场景要重新 build(镜像里的 data/ 是烤进去的);systemd / k8s 场景重启即可(数据文件随包安装)。
  2. 缓存是进程内的(in-process):不落盘、不跨副本共享。重启 = 冷缓存;k8s 里两个副本各有一份。 想持久化缓存是改网关实现,不是加 volume。
  3. A_GATEWAY_CONTACT 是联系邮箱、不是密钥,但强烈建议设成真实邮箱。 它写进 User-Agent,SEC、OpenAlex 等上游据此识别调用方,不带邮箱 SEC 直接 403。

Docker Compose

本机 / 单机 / 开发验证的首选。服务定义在 docker-compose.yml,宿主机端口用 PORT 覆盖(容器内永远是 8848)。

安装与配置

bash
git clone https://github.com/hamr-hub/a-source-gateway.git
cd a-source-gateway
cp .env.example .env
$EDITOR .env          # 至少把 A_GATEWAY_CONTACT 改成你的真实邮箱

make up                # = docker compose up -d --build

也可以不建 .env,直接在命令前面带环境变量:

bash
A_GATEWAY_CONTACT=you@example.com docker compose up -d

验证

bash
docker compose ps                       # STATUS 应为 healthy
docker compose logs -f gateway           # 看日志
curl -s http://127.0.0.1:8848/livez  | python3 -m json.tool
curl -s http://127.0.0.1:8848/readyz | python3 -m json.tool
curl -s "http://127.0.0.1:8848/v1/sources?q=制裁" | python3 -m json.tool
console
$ curl -s http://127.0.0.1:8848/livez | python3 -m json.tool
{
    "ok": true,
    "uptime_s": 500.4
}
$ curl -s http://127.0.0.1:8848/readyz | python3 -m json.tool
{
    "ok": true,
    "sources": 117,
    "offline": false
}

/livez = 进程活着;/readyz = 注册表已加载、能接流量(sources 为 0 时返回 503);/healthz = 健康。

回滚

bash
# 1) 回到上一个能用的 git 版本重新 build
docker compose down
git checkout <上一个好版本>
docker compose up -d --build

# 2) 只回滚配置(改错了 .env)
docker compose down && $EDITOR .env && docker compose up -d

镜像本身没有历史版本标签(a-source-gateway:local 是本地构建),回滚就是回到上一个能用的 git 版本重新 build。

i镜像里还有一次性 CLI

镜像内的 Python CLI 是 /usr/local/bin/a-source-gateway-cli(list / validate / bench / show)。 docker-compose.yml 里的 tools 服务默认是整段注释掉的,要用之前先把它打开:

bash
docker compose --profile tools run --rm tools list
docker compose --profile tools run --rm tools validate

systemd

单台长期运行的服务器。单元文件在 deploy/systemd/a-source-gateway.service, 运行参数样例在 deploy/systemd/env.example。

安装

bash
# Python 解析面(网关会拉起 python3 -m a_source_gateway.parser_worker)
# 系统 Python 3.10+ 即可;用发行包或 pip 装都行:
pip3 install a-source-gateway        # 装进系统 Python
# 或从源码装(仓库根):
pip3 install .

# 二进制:本地构建,产物在 bin/a-source-gateway
make gateway-build
sudo install -m 0755 bin/a-source-gateway /usr/local/bin/a-source-gateway

# 服务账号与目录
sudo useradd --system --home-dir /var/lib/a-source-gateway --shell /usr/sbin/nologin a-source-gateway
sudo install -d -m 0750 -o root -g a-source-gateway /etc/a-source-gateway
sudo install -d -m 0750 -o a-source-gateway -g a-source-gateway /var/lib/a-source-gateway

# 事实源(data/):Go 网关从工作目录和可执行文件目录逐级向上找 data/,
# 装到 /var/lib/a-source-gateway/data 就正好落在 systemd 的 WorkingDirectory 下。
sudo install -d -m 0750 -o a-source-gateway -g a-source-gateway /var/lib/a-source-gateway/data
sudo install -m 0640 -o a-source-gateway -g a-source-gateway data/source_inventory.csv \
     /var/lib/a-source-gateway/data/
sudo install -m 0640 -o a-source-gateway -g a-source-gateway data/source_inventory_cn.csv \
     /var/lib/a-source-gateway/data/
sudo install -m 0640 -o a-source-gateway -g a-source-gateway data/endpoints.json \
     /var/lib/a-source-gateway/data/
sudo install -m 0640 -o a-source-gateway -g a-source-gateway data/aliases.json \
     /var/lib/a-source-gateway/data/

# 单元文件
sudo install -m 0644 deploy/systemd/a-source-gateway.service /etc/systemd/system/a-source-gateway.service
sudo systemctl daemon-reload

Python 包原本也装出一个叫 a-source-gateway 的命令,和 Go 二进制同名 —— 所以先装 Python、再装 Go 二进制,让 Go 拿到这个名字,单元文件的 ExecStart=/usr/local/bin/a-source-gateway 才是网关本体。 网关只需要 Python 模块可导入(它拉起 python3 -m a_source_gateway.parser_worker),被覆盖的那个 CLI 命令不影响运行。

想跳过 Python:装 A_GATEWAY_PARSER=go(见下文配置),这时只需要 Go 二进制。 更新事实源:重新 install 那些 data/ 文件,然后 systemctl restart。

配置

bash
sudo install -m 0640 -o root -g a-source-gateway \
     deploy/systemd/env.example /etc/a-source-gateway/env
sudo editor /etc/a-source-gateway/env

EnvironmentFile=-/etc/a-source-gateway/env 前面的 - 表示文件缺失也不报错 —— 没配也能起,全部走默认值。

启动与验证

bash
sudo systemctl enable --now a-source-gateway
sudo systemctl status a-source-gateway
sudo journalctl -u a-source-gateway -f
bash
systemctl is-active a-source-gateway     # active
curl -s http://127.0.0.1:8848/livez
curl -s http://127.0.0.1:8848/readyz

回滚

bash
# 换回旧二进制
sudo install -m 0755 /path/to/previous/a-source-gateway /usr/local/bin/a-source-gateway
sudo systemctl restart a-source-gateway

# 配置改错了
sudo cp /etc/a-source-gateway/env.bak /etc/a-source-gateway/env
sudo systemctl restart a-source-gateway

旧的二进制要自己留一份 —— systemd 单元不会自动保留上一个版本。

Kubernetes

集群与多副本。清单在 deploy/k8s/,apply 顺序由 deploy/k8s/kustomization.yaml 的 resources 列表决定: ConfigMap → Deployment → Service(Service 放最后,避免流量打到还不存在的选择器上)。

部署

bash
kubectl create namespace a-source-gateway          # 一次
kubectl apply -k deploy/k8s/                              # ConfigMap → Deployment → Service

deploy/k8s/configmap.yaml 里的 A_GATEWAY_CONTACT 是占位值 you@example.com, 换成真实邮箱后重新 apply,并重启 Deployment 让新的环境变量生效:

bash
kubectl apply -k deploy/k8s/
kubectl -n a-source-gateway rollout restart deployment/a-source-gateway

凭据单独建、不进仓库(形状见 deploy/k8s/secret.example.yaml,整份是注释、不生效):

bash
kubectl -n a-source-gateway create secret generic a-source-gateway-secrets \
  --from-literal=A_GATEWAY_<某源>_KEY='<value>'

然后放开 deploy/k8s/deployment.yaml 里 secretRef 那段注释。

验证

bash
kubectl -n a-source-gateway rollout status deployment/a-source-gateway
kubectl -n a-source-gateway get pods -o wide
kubectl -n a-source-gateway port-forward svc/a-source-gateway 8848:8848
bash
curl -s http://127.0.0.1:8848/livez
curl -s http://127.0.0.1:8848/readyz

Service 是 ClusterIP(只暴露集群内),对外暴露交给 Ingress / Gateway,不要直接给公网。 默认副本数 2,滚动策略 maxUnavailable: 0 / maxSurge: 1,更新期间不会掉到 0 副本; preStop 里的 sleep 5 让 Pod 先从 Endpoints 摘掉再收 SIGTERM,在途请求不会被打断。

回滚

bash
# 回滚到上一个 ReplicaSet
kubectl -n a-source-gateway rollout undo deployment/a-source-gateway
kubectl -n a-source-gateway rollout history deployment/a-source-gateway

# 镜像回滚(改完重新 build / push 后)
kubectl -n a-source-gateway set image deployment/a-source-gateway \
  gateway=ghcr.io/hamr-hub/a-source-gateway:<上一个可用 tag>

本地二进制

开发调试用,不需要 Docker。Go 网关是主运行时;Python 那条是参照实现,两边读同一份 data/。

跑 Go 网关

bash
make gateway-run            # = make gateway-build && ./bin/a-source-gateway
make gateway-run PORT=9000   # 换端口

默认监听 127.0.0.1:8848。make gateway-run 会先编译出 bin/a-source-gateway,再前台启动它。

跑 Python 参照实现

bash
make install                # pip install -e .
make run                    # = a-source-gateway serve(uvicorn)
make run PORT=9000

仓库里的 make parity 会比对 Go 与 Python 从同一份 data/ 构建出的注册表是否一致。

验证与回滚

bash
curl -s http://127.0.0.1:8848/livez
curl -s http://127.0.0.1:8848/readyz
bash
# 部署前先留一份上一版二进制
cp bin/a-source-gateway bin/a-source-gateway.prev

# 出问题后:换回旧二进制再启动
cp bin/a-source-gateway.prev bin/a-source-gateway
./bin/a-source-gateway

# 或者换回上一个 git 版本重新编译
git checkout <上一个好版本>
make gateway-build

配置变量

全部走环境变量，每个变量都有默认值（下面列的是常用的几个，完整清单见 gateway/internal/config/config.go）。宿主机端口由 PORT 控制(仅 Docker Compose),容器内监听端口永远是 8848。

变量默认说明
PORT8848宿主机端口(仅 Docker Compose)
A_GATEWAY_HOST127.0.0.1监听地址;容器内必须 0.0.0.0,否则外部访问不到
A_GATEWAY_PORT8848监听端口
A_GATEWAY_CONTACT空联系邮箱,写进 User-Agent(不是密钥);不带邮箱 SEC 直接 403
A_GATEWAY_BUDGET_MS500单次调用总预算
A_GATEWAY_UPSTREAM_BUDGET_MS400留给上游请求的预算
A_GATEWAY_RESERVE_MS100留给解析与封装的余量
A_GATEWAY_CACHE_ENTRIES512进程内缓存条目上限
A_GATEWAY_CACHE_BYTES33554432进程内缓存字节上限
A_GATEWAY_CACHE_TTL_S900缓存 TTL(秒)
A_GATEWAY_PREWARM1启动预热
A_GATEWAY_PARSERautoauto / python / go;go = 纯 Go,不拉起 Python worker
A_GATEWAY_OFFLINE0离线模式:不发网络请求,只给元数据与已缓存数据
A_GATEWAY_DATA_DIR容器内 /app/data事实源目录;不设则用包内自带的一份
A_GATEWAY_URLhttp://127.0.0.1:8848MCP server 转发给 Go 网关的地址(见 MCP 集成)

镜像里有什么

路径是什么
/usr/local/bin/a-source-gatewayGo 网关(容器 ENTRYPOINT)
/usr/local/bin/a-source-gateway-cliPython CLI(list / validate / bench / show)
/usr/local/bin/healthcheck.py容器健康检查(打 /livez)
i为什么有两个同名 CLI

Python 包原本也装出一个叫 a-source-gateway 的命令,会和 Go 二进制撞名, 所以镜像里把它改名成了 a-source-gateway-cli。镜像以非 root 运行(uid/gid 10001),和 k8s 的 runAsUser: 10001 对齐。

排障

症状先查
/livez 不通docker compose logs gateway / journalctl -u a-source-gateway;容器起不来多半是数据文件没找到
/readyz 报 sources 为 0data/ 没进镜像 → 重新 build;或 A_GATEWAY_DATA_DIR 指错了
上游 403A_GATEWAY_CONTACT 没设或不是有效邮箱
响应带 degraded看 meta.errors[] 与 meta.fallback.upstream_url,里面直接写了原因和下一步
超时 / budget_exceeded端点 budget_ms 与上游实际延迟;必要时调小 page_size
Python worker 起不来A_GATEWAY_PARSER=go 可以先顶上(纯 Go 解析);which python3、包是否装在系统 Python 里
改了 data/ 没生效Compose 要重新 make up(= docker compose up -d --build);systemd / k8s 重启即可
容器起不来、报找不到数据文件systemd 场景检查 WorkingDirectory=/var/lib/a-source-gateway 下有没有 data/
